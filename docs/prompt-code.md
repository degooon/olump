# Промпт: как писать код

Парный к [prompt.md](prompt.md). Тот — про ошибки, которых не надо
повторять. Этот — про то, как должен выглядеть код, чтобы следующий проект
получился в том же стиле, а не как попало.

Примеры настоящие, из работающего проекта. Их можно показывать модели
как образец.

---

```
Пиши код в этом стиле. Примеры ниже — из моего рабочего проекта,
держи их как образец и не отклоняйся без причины.
```

## 1. Комментарии — главное отличие

Это то, что сильнее всего отличает мой код от обычного. Правило одно:

**Комментарий объясняет, почему так, а не что здесь происходит.**

Плохо — пересказ кода:

```js
// Получаем минимальную цену
const PRICE_MIN = Math.min(...PRICES);
```

Хорошо — то, чего в коде не видно:

```js
// Реальные границы цен каталога — для подсказок в пустых полях.
// Считаем из данных, чтобы подсказки не разошлись с товарами.
// Пока цен нет ни у одного товара, границ не существует — тогда подсказки
// в полях остаются пустыми. Без этой проверки Math.min по пустому списку
// вернул бы бесконечность, и в поле встало бы «∞».
const PRICES = PRODUCTS.map((p) => p.price).filter(Number.isFinite);
const PRICE_MIN = PRICES.length ? Math.min(...PRICES) : null;
```

**Называй, что сломается без этой строки.** Не «экранируем текст», а:

```js
// Экранирует текст, который попадает в HTML-шаблоны карточек. Пока товары
// лежали в коде, этого не требовалось — там всё было написано нами. Из CMS
// приходит что угодно: кавычка в названии «Диван "Зевс"» разорвала бы атрибут
// alt, а угловая скобка — всю разметку карточки.
export const esc = (v) => String(v).replace(/[&<>"']/g, (c) => `&#${ c.charCodeAt(0) };`);
```

**Помечай связанные места.** Если значение продублировано — скажи об этом
прямо в коде:

```js
// Телефон для звонка. Формат 7XXXXXXXXXX, без «+» и пробелов.
// Тот же номер показан в подвале — при смене правь оба места.
export const ORDER_PHONE = '79620018222';
```

**Объясняй, чего ты не сделал и почему.** Отказ от очевидного решения без
комментария выглядит как забывчивость:

```js
// WhatsApp намеренно не используется: с декабря 2025 Роскомнадзор заблокировал
// его в России, домены исключены из НСДИ. Ссылка вида wa.me у покупателя
// просто не откроется, и заказ до магазина не дойдёт.
```

**Пиши комментарии по-русски.** Код, названия переменных и файлов —
латиницей, комментарии и тексты интерфейса — русским.

**Разделяй файл на секции** заголовками одного вида:

```js
// ─── Каталог: фильтрация, карточки, отрисовка сетки ───
// ─── Состояние фильтров читаем прямо из формы ───
// ─── Каналы приёма заказов ───
```

**Не комментируй очевидное.** `// увеличиваем счётчик` над `count++` —
шум. Комментарии нужны там, где решение неочевидно, а не везде подряд.

## 2. Структура

**Один файл — одна ответственность.** В проекте двенадцать модулей:
каталог, корзина, окно товара, категории, навигация, сортировка,
состояние, работа с DOM, данные, утилиты, появление блоков, точка сборки.

**Один блок стилей — один файл.** Тридцать девять файлов в `blocks/`.
Порядок подключения задан явно в главном файле и прокомментирован,
потому что порядок в CSS — это каскад:

```scss
// ─────────────────────────────────────────────
//  Мебельный склад «Олимп» — точка сборки стилей
//  Один блок — один файл. Порядок подключения =
//  порядок в итоговом CSS, менять его осознанно (каскад!).
// ─────────────────────────────────────────────
```

**Обращения к DOM собери в один модуль.** Не ищи элементы по всему коду:
`dom.js` находит их один раз, остальные импортируют готовое.

**Данные отдельно от логики.** `data.js` умеет только одно: достать каталог
и отдать. Кто и как его показывает — не его дело.

## 3. JavaScript

**Ванильный, модулями ES.** Фреймворк — только если задача его требует,
и тогда с объяснением, почему без него нельзя.

**Именованный экспорт.** Никаких `export default`.

**Стрелка для короткого выражения, `function` для процедуры:**

```js
export const fmt = (n) => `${n.toLocaleString('ru-RU')} ₽`;

function priceOf(input, noLimit) {
  const n = parseInt(input.value, 10);
  return Number.isFinite(n) ? n : noLimit;
}
```

**Проверяй данные на входе, а не доверяй им.** Всё, что пришло снаружи —
из хранилища, из CMS, из адресной строки — может быть мусором:

```js
return new Map(entries.filter(([id, qty]) =>
  KNOWN_IDS.has(id) && Number.isInteger(qty) && qty > 0));
```

**Никогда не вставляй чужой текст в разметку без экранирования.**

**Отступ два пробела, точка с запятой обязательна, кавычки одинарные.**

**Внутри шаблонной строки — пробелы в фигурных скобках**, если внутри
не одна короткая переменная: `` `&#${ c.charCodeAt(0) };` ``.

**Выравнивай значения в объекте, когда это делает его читаемым:**

```js
return {
  cat:    data.get('cat') || 'all',
  q:      (data.get('q') || '').trim().toLowerCase(),
  min:    Math.min(from, to),
  max:    Math.max(from, to),
};
```

**Магические числа выноси в константы с именем и комментарием.**

**Версионируй ключи хранилища:**

```js
// Ключ localStorage; версия в имени спасёт от старого формата при изменениях.
const CART_KEY = 'olimp-cart-v1';
```

## 4. Устойчивость

**Страница не должна падать из-за данных.** Любой неожиданный ответ —
это повод показать разумный запасной вариант, а не пустой экран:

```js
// Читаем данные из разметки. Возвращаем null при любой неожиданности: сайт
// со старыми товарами лучше, чем пустая страница и ошибка в консоли. Каталог,
// который не удалось разобрать, — повод чинить тему, а не ронять витрину.
```

**`try` без падения, с объяснением в пустом `catch`:**

```js
try {
  localStorage.setItem(CART_KEY, JSON.stringify([...cart]));
} catch {
  // приватный режим или переполненное хранилище — просто не сохраняем
}
```

Пустой `catch` без комментария — ошибка. Пустой `catch` с объяснением,
почему здесь можно ничего не делать, — решение.

**Прогрессивное улучшение.** Разметку отдаёт сервер, скрипт её улучшает.
Если скрипт не выполнился, страница остаётся читаемой — и для человека,
и для поисковика.

**Учитывай системные настройки пользователя:**

```js
export const smooth = matchMedia('(prefers-reduced-motion: reduce)').matches ? 'auto' : 'smooth';
```

## 5. Стили

**Строгий БЭМ.** Линтер настроен так, что иначе не пройдёт:

```
selector-max-type: 0              никаких селекторов по тегам
selector-max-compound-selectors: 2
selector-max-specificity: 0,3,1
```

Исключения только там, где разметка приходит извне (содержимое редактора
CMS) — и тогда исключение прописывается в конфиг линтера явно, с указанием
файла.

**Цвета, шрифты, тени — переменными в одном месте.** В коде блока
`var(--accent-dark)`, а не `#8F3D1C`.

**Комментируй хитрости, а не свойства:**

```scss
// Фолбэк одним url — для браузеров без image-set; ниже ретина-набор.
// Autoprefixer сам добавит -webkit-image-set для старых Safari.
```

**Отключённое оставляй с инструкцией, как вернуть:**

```scss
// Рисованная сцена скрыта: её место занял фото-фон с диваном.
// Чтобы вернуть иллюстрацию — поставь display: block и убери фон у .hero.
```

## 6. Разметка

**Семантика и доступность не по остаточному принципу.** `aria-label`
у иконок, `role` у списков, видимый фокус, ловушка фокуса в модальных окнах,
`visually-hidden` для подписей полей.

**Комментарий над неочевидным блоком** — прямо в HTML:

```html
<!--
  Ссылка на карты, а не просто текст: с телефона это один тап
  до маршрута. Для склада, куда приезжают смотреть мебель,
  это важнее любого другого контакта.
-->
```

**Картинки — с `srcset`, `sizes`, `alt` и заданной пропорцией**, чтобы
страница не прыгала при загрузке.

## 7. Если проект на CMS

**Разметка живёт в одном месте.** Шаблон CMS собирается из исходника
сборщиком, а не поддерживается руками параллельно.

**Экранируй всё, что печатаешь:** `esc_url`, `esc_attr`, `esc_html`.

**Данные отдавай двумя способами** — готовой разметкой для поисковика
и структурой для скрипта. Формат структуры опиши в отдельном файле
и укажи, что менять его надо с обеих сторон.

**Настройки — константами в начале файла**, чтобы их было видно:

```php
// Номер счётчика Яндекс.Метрики. Пустой — счётчик не печатается.
const OLIMP_METRIKA_ID = '';
```

**Не считай статистику по себе:**

```php
// Свои визиты не считаем: вошедший в админку — это владелец или разработчик,
// а не покупатель. На сайте с десятком посетителей в день такие заходы
// искажают картину сильнее всего.
```

## 8. Совместимость

**Планка — Baseline widely available.** Возможность считается доступной,
если её поддерживают все основные браузеры не меньше двух с половиной лет.
Проверяется по датасету `web-features`, а не по ощущениям.

**Не подключай полифилы «на всякий случай».** Либо возможность прошла
планку и полифил не нужен, либо не прошла и её не надо брать.

## 9. Проверки

Настрой с самого начала и гоняй одной командой:

```bash
npm run lint    # eslint + stylelint + linthtml + editorconfig
```

**Линтер — это договор, а не помеха.** Если правило мешает — обсуди
исключение и пропиши его в конфиг с комментарием. Не отключай молча.

**Настоящий браузер для проверки поведения.** Playwright, минимум два
движка — Chromium и WebKit. Проверять: раскладку на разных экранах,
работу с клавиатуры, скорость на замедленном процессоре.

## 10. Чего не делать

**Не тащи библиотеку ради одного эффекта.** У меня GSAP весил 30 КБ ради
появления блоков при прокрутке; замена на `IntersectionObserver` заняла
пятьдесят строк и убрала 87% веса скрипта.

**Не пиши код без комментария там, где решение неочевидно.** Через месяц
неочевидное станет непонятным, в том числе тебе.

**Не дублируй данные.** Один источник, остальное выводится из него.

**Не оставляй заглушек без пометки.** Если значение временное — скажи
об этом в комментарии и объясни, откуда возьмётся настоящее.

**Не молчи о компромиссах.** Если решение принято из-за ограничения
хостинга, срока или чужого API — запиши это рядом с кодом. Иначе следующий
человек примет его за твою архитектурную мысль.
